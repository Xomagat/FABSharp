# FAB#

FAB# — компилируемый язык программирования, написанный на C++ с использованием LLVM.
Программа на `.fab` превращается в самостоятельный исполняемый файл (Windows и Linux, x86-64), без интерпретатора и лишних зависимостей.

> [!WARNING]
> Версия 0.1, язык в активной разработке: синтаксис и набор возможностей могут меняться.

```cpp
define main() -> int
{
    writeln "Hello, World!";
}
```

## Сборка

Требования:

- CMake 3.31+ и компилятор с поддержкой C++20
- LLVM (на Windows папка `llvm/` рядом с проектом)
- Linux: `glibc-static` и статическая библиотека `libzstd`

```bash
cmake -B build
cmake --build build
```

После сборки рядом с компилятором появятся папки `lib/` (стандартная библиотека) и `tools/` (линковщик и runtime-файлы).

## Использование

```bash
fab hello.fab      # компиляция
./hello            # запуск (Linux)
hello.exe          # запуск (Windows)
```

| Команда | Действие |
|---|---|
| `fab file.fab` | компилирует программу |
| `fab --help` / `fab -h` | показывает справку |
| `fab --version` / `fab -v` | показывает версию |

Подробности о языке смотрите в документации.

## Как присоединиться

К разработке можно свободно присоединиться!

1. Сделайте форк репозитория на GitHub.
2. Склонируйте **свой** форк:
   ```bash
   git clone https://github.com/<ваш-логин>/FABSharp.git
   cd FABSharp
   ```
3. Добавьте upstream-репозиторий, чтобы синхронизироваться с основной веткой:
   ```bash
   git remote add upstream https://github.com/Xomagat/FABSharp.git
   ```
4. Посмотрите список [issues](https://github.com/Xomagat/FABSharp/issues): метка `help wanted` отлично подходит для первого вклада.
5. Создайте отдельную ветку, внесите изменения и откройте Pull Request.

## Кодекс поведения

Будьте уважительны к другим участникам. Оскорбления, токсичное поведение и дискриминация недопустимы.

## Требования к коду

- Сохраняйте структуру проекта: парсер в `Parser/`, узлы AST в `Parser/AST/`, генерация кода в `CodeGen/`, стандартная библиотека в `lib/`.
- Новые возможности языка должны соответствовать существующему синтаксису; если вы его меняете, обновите документацию (`DOC-RU.md` и `DOC-EN.md`).
- Оставляйте [комментарии](#комментарии) по правилам ниже.

## Комментарии

В начале нового файла напишите комментарий:

```cpp
//
// Created by (ваше имя или ник) on DD.MM.YYYY
//
```

Дальше комментируйте только то, что нужно пояснить: что делает функция, класс, нетривиальное условие или цикл.

## Коммиты и сообщения

Используйте понятные сообщения коммитов, желательно в таком формате:

```
краткое описание

Более подробное объяснение при необходимости: что и почему
изменено, а не как (это видно из diff).
```

Один коммит — одно логическое изменение, и сообщение должно описывать именно его.

Пример:

```
fix continue target in for loop codegen
```
