# FAB#

FAB# — компилируемый язык программирования, написанный на C++ с использованием LLVM.
Программа на `.fab` превращается в самостоятельный исполняемый файл (Windows и Linux, x86-64), без интерпретатора и лишних зависимостей.

> [!WARNING]
> Версия 0.2, язык в активной разработке: синтаксис и набор возможностей могут меняться.

```cpp
define main() -> int
{
    list<string> words = "fab sharp language".split(" ");

    for (int i = 0; i < words.length(); i += 1)
        writeln words[i].capitalize();

    return 0;
}
```

📖 Документация: [Русский](DOC-RU.md) · [English](DOC-EN.md)

## Возможности

- Типы `int`, `long`, `short`, `float`, `double`, `bool`, `char`, `string`, а также `list<T>` и `dict<K,V>` с литералами `[...]` и `{...}`.
- Условия, циклы `while` / `do-while` / `for`, `break` и `continue`.
- Функции с перегрузкой и рекурсией, точка входа `main` необязательна.
- Методы у всех типов: `"text".to_upper()`, `n.to_str()`, `nums.sort()`, `ages.get_or("Аня", 0)`.
- Стандартная библиотека: методы типов подключены всегда, `math` подключается через `use math;`.
- Разбиение программы на файлы через `use "file.fab";`.

## Сборка

Требования:

- CMake 3.31+ и компилятор с поддержкой C++20
- LLVM (на Windows папка `llvm/` рядом с проектом)
- Linux: `glibc-static` и статическая библиотека `libzstd`

```bash
cmake -B build
cmake --build build
```

CMake собирает два результата: компилятор `fab` и статическую библиотеку времени выполнения `fabstd` (`libfabstd.a` на Linux, `fabstd.lib` на Windows). После сборки рядом с компилятором появляются:

- `lib/` — библиотека времени выполнения и манифесты стандартной библиотеки;
- `tools/` — линковщик и runtime-файлы (на Linux копируются статические файлы glibc).

Компилятор ищет эти папки рядом со своим исполняемым файлом, поэтому при переносе `fab` в другое место переносите `lib/` и `tools/` вместе с ним.

## Использование

```bash
fab hello.fab      # компиляция
./hello            # запуск (Linux)
hello.exe          # запуск (Windows)
```

| Команда | Действие |
|---|---|
| `fab file.fab` | компилирует программу |
| `fab --help` / `fab -h` | показывает справку |
| `fab --version` / `fab -v` | показывает версию |

Подробности о языке смотрите в документации.

## Структура проекта

| Папка / файл | Что внутри |
|---|---|
| `main.cpp` | точка входа компилятора: чтение файла, запуск лексера, парсера, кодогенерации и линковщика |
| `Parser/` | лексер (`Lexer`), токены (`Token`, `TokenType.h`) и парсер (`Parser`) |
| `Parser/AST/` | узлы дерева разбора: выражения (`*Expression.h`) и команды (`*Statement.h`); каждый узел умеет генерировать LLVM IR методом `codegen` |
| `CodeGen/` | контекст кодогенерации (`CodegenContext.h`) и сборка объектного файла (`Compile.cpp`) |
| `libs/STDLibInfo.h` | таблицы символов стандартной библиотеки, которые заполняются из манифестов |
| `lib/types/` | методы типов: `string`, `char`, `bool`, `integers` (`short`, `int`, `long`, `float`, `double`), `list`, `dict` — по паре файлов `.cpp` + `.manifest` |
| `lib/libs/` | подключаемые библиотеки (`use math;`) |
| `test.fab` | пример программы для проверки |

## Стандартная библиотека

Стандартная библиотека состоит из двух частей: реализация на C++ (компилируется в `fabstd`) и **манифест** — текстовый файл, который объясняет компилятору, какие функции есть и с какими типами. Манифесты из `lib/types/` загружаются всегда, остальные — по команде `use имя;`.

Строка манифеста описывает одну функцию или метод:

```
# функция:    имя        символ          результат : аргументы
pow           fab_powi   int             : int, int

# метод:      тип.имя    символ          результат : получатель, аргументы
string.trim   fab_trim   string          : string

# метод коллекции (T, K, V подставляются компилятором)
list<T>.get   fab_list_get   T           : list<T>, int
dict<K,V>.get fab_dict_get   V           : dict<K,V>, K

# константа:  const ИМЯ тип значение
const PI double 3.14159265358979323846
```

Правила:

- В C++ функции объявляются как `extern "C"` с префиксом `fab_`, чтобы имена не искажались.
- У метода первым аргументом всегда идёт получатель (тип слева от точки).
- Для `list<T>` и `dict<K,V>` к символу автоматически дописывается суффикс типов: `fab_list_get` для `list<int>` превращается в `fab_list_get_int`. Значит, в C++ нужна реализация для каждого поддерживаемого типа элемента (удобно делать макросом, см. `lib/types/list.cpp`).
- `bool` приходит из компилятора как `i1`, а `char` как `i8`: старшие биты аргумента не определены, поэтому в C++ их нужно маскировать.
- Новый `.cpp` нужно добавить в цель `fabstd` в `CMakeLists.txt`.

## Как присоединиться

К разработке можно свободно присоединиться!

1. Сделайте форк репозитория на GitHub.
2. Склонируйте **свой** форк:
   ```bash
   git clone https://github.com/<ваш-логин>/FABSharp.git
   cd FABSharp
   ```
3. Добавьте upstream-репозиторий, чтобы синхронизироваться с основной веткой:
   ```bash
   git remote add upstream https://github.com/Xomagat/FABSharp.git
   ```
4. Посмотрите список [issues](https://github.com/Xomagat/FABSharp/issues): метка `help wanted` отлично подходит для первого вклада.
5. Создайте отдельную ветку, внесите изменения и откройте Pull Request.

## Требования к коду

- Сохраняйте структуру проекта: парсер в `Parser/`, узлы AST в `Parser/AST/`, генерация кода в `CodeGen/`, стандартная библиотека в `lib/` (методы типов в `lib/types/`, подключаемые библиотеки в `lib/libs/`).
- Новые возможности языка должны соответствовать существующему синтаксису; если вы его меняете, обновите документацию (`DOC-RU.md` и `DOC-EN.md`).
- Новые функции и методы стандартной библиотеки добавляйте парой: реализация в `.cpp` и строка в `.manifest` (см. [Стандартная библиотека](#стандартная-библиотека)). Не забудьте обновить таблицы в документации.
- Оставляйте [комментарии](#комментарии) по правилам ниже.

## Комментарии

В начале нового файла напишите комментарий:

```cpp
//
// Created by (ваше имя или ник) on DD.MM.YYYY
//
```

Дальше комментируйте только то, что нужно пояснить: что делает функция, класс, нетривиальное условие или цикл.

## Коммиты и сообщения

Используйте понятные сообщения коммитов, желательно в таком формате:

```
краткое описание

Более подробное объяснение при необходимости: что и почему
изменено, а не как (это видно из diff).
```

Один коммит — одно логическое изменение, и сообщение должно описывать именно его.

Пример:

```
fix continue target in for loop codegen
```
